# Deterministic queued-reaction playback

`scripts/test-integrated-reaction-playback.py` extends the native result-object
checks with actual mGBA rendering, fixed menu inputs, turn completion and native
suspend/cold resume. It runs through `Test Expansion.ps1` using the declared
`test-integrated-reaction-playback` step in `integration-test-plan.json`.
The primary agent owns implementation and review; no testing agents run.

## Fixture and instrumentation

The starting battle is generated by the existing hash-verified native Giza
fixture. Four fixed Wait turns reach Marche. A real Human, Bangaa or Moogle unit
is positioned as the recipient, using controlled allegiance, equipment, job,
mastery and ordinary HP/attack/defense inputs. Its original race and loaded
racial sprite are preserved. Marche uses native Move to (2,12), then Fight
against the adjacent opponent at (3,12). All action selection, hit resolution,
reaction construction, damage, rendering and subsequent turns run in the game.
This controlled allegiance fixture is not a claim about a campaign AI build or
the complete job-change/sprite-loading workflow.

Bard reactions use a Moogle Black Mage with no instrument. For these cases
alone the attacker is declared hostile and the reactor player-controlled before
inputs. This preserves a native next-turn menu before the Moogle's short charge
expires; FFTA cannot suspend after an action has already been spent. No faction,
charge, reaction result or saved state is modified after execution.

The test-only ROM changes the installed A433C entry pointer to a wrapper in an
asserted-erased bank at 13F0000. The wrapper restores the normal C stack ABI,
fixes the declared RNG seed, invokes the real installed shared executor through
its original push-r3 entry protocol, and copies result summaries afterward.
It does not inject a result, HP amount, reaction claim or rendered frame.
The log occupies test-only 0203FF50..0203FFEF; neighboring guards and both
transient action roots are checked. No production code or save schema changes.

The log records the native original actor/action and up to four real result
objects, including reactor/recipient identity, flags, signed HP/MP and special
display amount. Its overflow check fails rather than silently accepting a
truncated reaction list. The instrumented image and source image have separate
hashes. All game images, saves, screenshots and logs remain ignored.

## Scenarios and limits

Counter Draw runs at seeds 0, 1, 3, 7, 15 and 18; Absorb Damage and Vengeful
Pulse run at seeds 0, 3 and 18. The Bard extension adds Magick Boost and Encore
at seeds 0, 3 and18. Each has equipped and disabled controls:36 scenarios
(the preceding accepted checkpoint had24). The scripts retain
native output and regularly spaced frames throughout 1,800 playback frames,
require non-vacuous reaction results, check changing rendered frames, and
verify rendering does not reapply HP/MP effects or alter AP/inventory. Move and
Fight consume both commands, so the script confirms the native facing prompt
before requiring the next unit's command menu.

The extended batch saves after a positive instance of each reaction through
native Save Now, boots a fresh emulator with the ordinary uninstrumented
candidate, and uses fixed title/resume inputs. Native HP/MP, AP/inventory,
owned state and Counter Draw's Centered buff are compared. The Bard extension
additionally requires a positive charge/Haste before saving and compares the
owned record and native Haste after cold resume. Read-only owned
accessors execute on cloned memory; they never repair the live game or save.

Rendered frame changes and successful turn return are playback evidence, not
OCR recognition of the banner or certification of every animation frame.
Gil Snapper, Dark Ward and Chemist reactions require their own playback
scenarios. Full campaign, law, AI, job-change, equipment/AP/acquisition and
every save lifecycle remain distinct acceptance obligations.
