## Implementation and ownership

The existing manager-owned enchanted-Fight receipt at workspace offset2620
grows from32 to64 bytes; the allocated pool grows from2640 to2660 hex bytes.
Its established component identity fields stay at their old offsets. Fourteen
16-bit masks at offset32 record successful custom setters for each result
object's up-to15 recipient rows. Prediction now uses the final four bytes for
a synchronous, authenticated query-owner pointer, restored before returning.
No native unit/status bits, saved records, save schema or global reservation
change. Allocation, zeroing, reuse and retirement use the existing manager.

The authenticated A433C result wrapper binds the container/actor/wrapper before
effects execute. Each of the five setters records only after successful
storage, after its real hit, HP, Immunity and Chemist prevention gates. A
refresh is an application even when its bytes do not change. Wound uses its
setter's return value, rather than checking whether an old wound survives.
Queries and reaction origins cannot record a primary application.

The late selector authenticates the original container, acting wrapper,
action, recipient wrapper and exact native mask address. It reads the receipt
instead of the current timer. Thus a later cure cannot erase an earlier
violation, and a pre-existing status cannot fabricate a new application.
Foreign/copied masks and retired result containers are rejected. The next
primary action clears the receipt. Ordinary actions without an enchanted
Fight component do not create records.
