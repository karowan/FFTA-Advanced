Run `./Build Expansion.ps1 -CompareCurrent` from PowerShell. Supply `-Python`
with your Python executable if the local default differs. Git, Node.js,
PowerShell and the local tools recorded in `notes/reproducible-toolchain.json`
must be installed. The clean USA ROM belongs at `roms/clean/FFTA_US_clean.gba`
with SHA1 `4ac05441f4de70a4ec3dd932116346c61b8783d9`.

The command creates a new private folder under `build/reproducibility/`. It
copies the current versioned source files, pinned compiler/assembler/engine
inputs and clean ROM into a workspace. It copies no existing build outputs,
fixtures, save files or generated manifests. Tools and the ROM are independent
copies, with file hashes checked after copying. Unrelated untracked files are
excluded. No player game, save or current integration manifest is replaced.

The stages are:

1. Build the vanilla+ foundation from the clean ROM and recorded upstream
   engine inputs, applying the versioned local fixes.
2. Use the bootstrap source commit pinned in `notes/engine-bootstrap.json` to
   generate the registry, compile the shared engine and assemble job/content,
   inventory/AP, command, action, display, Combo and combat tables/hooks.
3. Restore current sources, then build Samurai and the shared persistent
   job-state layer.
4. Compile Chemist, Dark Knight and Viking against that common base.
5. Compose the complete integrated image, including the other job modules,
   original-ROM-derived terrain assets, recovery content and help text.

Each stage has its own complete log. The final report records source and tool
hashes, runtime versions, all commands and output ROM hashes. The pointer to the
latest report is `build/reproducibility/latest.json`. Reports and complete stage
logs remain after success or failure. The copied workspace is removed by default;
use `-KeepWorkspace` to retain it for diagnosis. Retention may later prune older
workspace copies; it preserves their reports and logs.

The private Git checkout must contain the pinned bootstrap commit, or the fresh
public source tree must contain its authenticated `bootstrap/index.json` bundle.
The three gameplay-profile overrides use the same bundle when present. The
source loader fails if a bundled file differs from its recorded hash. Only build
code/data is copied from the old revision; historical prose is not a build input.
This source transport was verified byte-for-byte, including the layout adapter;
the cleanup did not rerun the complete ROM build. Later layers depend
on that engine's original function layout and replace its relevant functions;
compiling all modern source into the first stage would introduce references to
providers that do not yet exist. The driver exports historical **source**, builds
it anew, verifies the expected engine/combat hashes, then restores current
source before building the later layers. Both source inventories are recorded.
No frozen engine binary or intermediate ROM is required as an input.

The initial source commit already included four assembly-wrapper repairs that
postdate its compiled bootstrap. `scripts/engine_bootstrap_source.py` reconstructs
those four older entry forms and the pre-A9 direct-action predicate from checked
source patterns solely for this stage.
The entire compiled engine must match its pinned hash. This compatibility source
is never installed over the current engine source or applied to the final image;
current replacement layers still compile after restoring current sources.
The build also checks that all four native entry hooks leave those historical
wrapper targets in the final image.

`-CompareCurrent` requires byte-for-byte equality with the candidate named by
`build/expansion/probes/integrated-jobs/current.json`. Without that switch, the
command still requires a complete clean build and verifies output hashes, but
does not claim equivalence with an older tested image. Rebuilding an identical
image does not warrant rerunning unrelated gameplay tests. A different image
needs a source/change audit before deciding which checks are relevant.

For deterministic acceptance through the project's runner, select only:

```powershell
./Test Expansion.ps1 -Plan scripts/integration-test-plan.json -Only test-clean-source-rebuild
```

This is a build-reproducibility check. It does not run the full integration
suite, regenerate battle fixtures or certify untested gameplay. The build-only
foundation option and shared engine's `-SkipTests` keep those responsibilities
separate. Final gameplay acceptance and player patch packaging remain the
release gates in `IMPLEMENTATION-CHECKLIST.md`.

Tool acquisition provenance is recorded in `notes/tool-provenance.json` and
the setup/research documentation. `notes/reproducible-toolchain.json` fixes the
exact local inputs used for this build. Update those pins deliberately when
upgrading dependencies; do not bypass a mismatch. ROMs, copied tools, generated
images and logs are private ignored files, never Git content.
